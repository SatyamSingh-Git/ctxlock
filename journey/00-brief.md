## The screenshots

The source was a PDF titled *Keynote Summary: Rent the Intelligence, Own the Context*. The keynote was Prukalpa Sankar's opening talk at Atlan's Context Conference on 2026-10-28.

### Screenshot 1: page 3, "05 · How to fix it"

**Three principles for managing context**

**Principle 1: Build context for agents, not humans.** Agents don't retrieve context the way you'd expect, and the format matters a lot.

| | |
|---|---|
| Agents opening a given skill (low end) | 46% |
| Agents loading all needed skills | 49% |
| …with a few distracting skills added | 31% |
| Vercel: context as a skill | 53% |
| Vercel: same context as an index | 100% |

More context can make things worse: with distracting skills, task success fell from 51% to 44%. Different jobs need different artifact types: skills, certified metrics, ontologies, tools, agent operating procedures.

**Principle 2: Manage context like code.** Context is now a production dependency, so it needs a "GitHub for context": collaborative authoring, versioning, dependency tracking, testing and evals. This solves the collaboration wall.

**Principle 3: Treat context as a compounding asset.** Agent traces and user feedback are a goldmine. Route that feedback to the right owner, fix once, and everyone benefits. Example:

1. User asks: "What is our Q3 net recurring revenue?"
2. User replies: "I actually wanted it by segment."
3. Feedback reaches the metric owner.
4. Owner adds a segment dimension.
5. Fix ships to everyone in the company.

### Screenshot 2: page 2, "A 'nervous system' for context" and "04 · Where companies get stuck"

**A "nervous system" for context.** A new kind of system of record that links three things across every tool, team and model, with the *context nervous system* at the centre:

- **Actors** (people + agents): who does the work, meaning people and, now, agents working side by side.
- **Artifacts** (skills, metrics, ontologies): the context actors rely on, meaning skills, tools, metrics, ontologies. These are production dependencies, so manage them like software.
- **Activity** (traces, outputs, feedback): what actually happened, meaning every agent trace, output and human "that's right" or "fix it". Without it, AI quality can't improve.

**The three walls everyone hits**

- **Wall 1, Accuracy.** *Can I trust it?* A Fortune 100 bank launched thousands of analytics agents; within months **90% were abandoned** because the business didn't trust them.
- **Wall 2, Collaboration.** Marketing changed its positioning, but the sales agent kept pitching the old version, and nobody knew what else depended on it.
- **Wall 3, Portability.** A global automaker's CIO: "I don't want my business IP locked into one platform." New models and platforms keep arriving.

### Screenshot 3: page 4, "Why a standard?" and "07 · Why it matters"

**Why a standard?** Open formats like Agent Skills and AGENTS.md exist, and tools like Claude Code, Codex and Copilot read them, but there is no common layer making them work together, much like the data world before Iceberg.

**The stakes are real**

- **+29%**: more breast cancers found by radiologists with AI help in Sweden.
- **2 years** of learning in just six weeks with an AI tutor in Nigeria.
- **1 fake policy**: an airline chatbot invented a bereavement fare policy. Not a dumb model, just missing context.

Data without context doesn't just give a wrong number; it gives a real person a wrong outcome. The people who do governance, catalogs, ontologies and knowledge management, work once called "boring", now decide **what AI is allowed to believe**. New roles are coming: **context engineers** and **context modelers**.

> **One line to remember:** Models will keep getting smarter and cheaper for everyone. Your edge is the context only you have, so rent the intelligence, but own the context.
