# Decisions

Every significant decision, why it was made, and whether it still stands. Reversals are kept rather than edited away, because the reversal is usually the more useful record.

## Direction

| # | Decision | Reasoning | Status |
|---|---|---|---|
| D1 | Research before asking product questions, in eight parallel tracks | The brief asked for deep research first, and "who is it for?" can't be answered well before you know what exists | Stands. It surfaced the open gap and the reuse inventory |
| D2 | Invent no new context file format | AGENTS.md, Agent Skills and MCP are governed by AAIF and read by about 80 agents | Stands |
| D3 | Reuse open-source code and published methods wherever they fit, license-checked, with credit | Satyam's instruction: "you can always use it anywhere and everywhere needed" | Stands. ctxlock depends on rulesync, agnix and promptfoo rather than rebuilding them |
| D4 | Build the layer above the formats: dependency graph, behavioral CI, load telemetry joined to sources, feedback loop | The research found all four missing in the open; only closed products have pieces | Stands |
| D5 | First user: developer teams running several coding agents | Satyam's call. The formats are open and the agents observable, so it is fast to prove | Stands |
| D6 | Open source, Apache-2.0 | Satyam's call (OSS). Apache-2.0 for its patent grant, and because it is compatible with every reuse pick | Stands |
| D7 | Name: ctxlock, replacing ContextFS | ContextFS collided with contextfs.ai, a paid AI-memory product. ctxlock was free on GitHub, npm, PyPI and crates.io, and unregistered on four domains | Stands. Trademarks not yet checked (open item before 1.0) |
| D8 | Phase order: behavioral CI → graph → loop → business context → open specs | Each phase is provable on its own; CI gives value on day one | Stands |

## Mechanism

| # | Decision | Reasoning | Status |
|---|---|---|---|
| D9 | Trust metadata lives in a `ctxlock.yaml` registry, not in frontmatter | AGENTS.md has no frontmatter, Codex would inject YAML as text against its 32 KiB cap, and HTML comments fail lint L1 | Stands |
| D10 | PR checks lead with probes, units loaded and cost; full statistical evals run on a schedule or label | The builder check showed a per-PR suite detects only swings of about 10 points or more, while real harms are 0.5–3 points | Stands |
| D11 | LLM-drafted probes are allowed, reviewed once and committed | Probes are tests, not context; the evidence against generated context is about context | Stands, untested |
| D12 | In phase 1, `ctxlock build` reports and fills missing targets, and never overwrites | Teams maintain their files by hand; overwriting them is a migration | Stands |
| D13 | Predict each agent's loading, then verify it. Claude Code via real hook events; Codex via its own ported open-source tests | No Codex access | Stands |
| D14 | Isolate eval runs with throwaway copies, run-scoped `--settings` hooks and observe-and-deny probes, instead of Docker | No Docker available, and this is cheaper and safer | Stands, unproven until spike S1 |
| D15 | Count the per-PR budget in runs and minutes, not dollars | Runs use a Claude Max subscription | Stands |
| D16 | agnix is an opt-in adapter; skill-spec checks (L0) are native | Discovery depends on L0, and agnix needs `npx`/network | Stands |
| D17 | No `tinyglobby` dependency | Git lists ignored `CLAUDE.local.md` files itself; non-git folders need only a small walker | Stands (Task 1) |
| D18 | L8 "excessive procedure" is `info`, not `should` | It is a heuristic until evals can validate it | Stands |
| D21 | A symlink makes the unit it points to visible at the symlink's path, for every kind of unit | The AGENTS.md FAQ recommends `ln -s AGENTS.md CLAUDE.md`; Claude Code then reads AGENTS.md through that link, and both agents share one file | Stands (Task 2) |
| D22 | Frontmatter is parsed only for rules and skills | No agent gives `AGENTS.md` or `CLAUDE.md` frontmatter any meaning, and a markdown file that opens with `---` would raise a false error | Stands (Task 2) |
| D23 | Claude Code's always-on and skill-listing totals are reported without a limit | Claude Code documents no total cap on always-on instructions. The skill listing does have one, 1% of the context window, but its unit (tokens or characters) is undocumented, and an invented number would raise false alarms | Stands, corrected after the batch-1 review: the first version said neither had a cap |
| D24 | Codex predictions are checked by Codex's own loader tests, ported with the upstream commit recorded | The concrete form of D13; the tests encode Codex's behaviour more precisely than its docs | Stands (Task 5) |
| D25 | Readers serve only the files they list; discovery follows in-repo symlinks itself | One place decides what a link may reach, so no lookup can read through a link out of the repository | Stands (batch-1 review) |
| D26 | Unit IDs are `<kind>/<path>`, not the design's `<kind>/<name>` | Names collide across directories: two skills called `review`, two rules called `style` | Stands for now; decide before lockfiles in phase 2 |
| D27 | Each hook, MCP server, command, approval or endpoint variable in an agent's config gets a fingerprint: a sha256 of its file, its identity and its value, not its position | `ctxlock diff` flags a PR that adds or changes one. Reordering a file should not trip it, and a hash keeps tokens in `env` out of PR comments | Stands (Task 7) |
| D28 | The L2 inventory follows each vendor's current source or docs, not the plan's list of keys | The plan's VS Code key, `chat.tools.autoApprove`, has been renamed, and current VS Code ignores it in a repo; the settings VS Code still honours there, and Codex's and Claude Code's code-running settings, were missing | Stands (Task 7); pinned to the commits and pages in the code comments |
| D29 | A gitignored file the agent still uses on this machine is read locally: `CLAUDE.local.md` and `.claude/settings.local.json` | Claude Code loads the first and runs the hooks in the second. CI never sees either, since it reads git refs | Stands (Task 7 extended D17's rule to settings) |
| D30 | `ctxlock diff` judges a pull request with the base branch's `harnesses`, `limits` and `lint` settings, not the pull request's own | The check exists partly to catch hostile changes; a pull request that could set `L1-hidden-unicode: off` in the same change would pass itself. Settings changes take effect on merge, like CODEOWNERS | Stands (Task 12) |
| D31 | The dogfood pass fixed `should` and `info` false positives too, not only `must` ones, wherever a reader would dismiss the finding on sight and a rule could tell the same thing from the repository | The plan asked only for `must` fixes, and there were no `must` findings. But a team that sees 30 wrong findings in its first `lint` run stops reading the rest, including the 18 real stale paths in sentry. Where telling right from wrong needs to know what a name refers to (a file in another repository, a branch name), the rule is left alone and `lint.ignore` is the answer | Stands (Task 14) |
| D32 | `L9-stale` counts a path as present when it is gitignored, or when it exists under another folder | Gitignored paths are outputs, and monorepo instructions name paths relative to a package. The cost is false negatives: a really stale path that happens to be gitignored, or that matches a file in another package, goes unreported. A skill's own `scripts/`, `references/` and `assets/` are never matched elsewhere | Stands (Task 14) |
| D33 | Only `L2-exec-config-changed` controls the gate on execution-affecting changes. `diff` compares the full inventory, whatever `L2-exec-config`'s severity or `lint.ignore` say | Quieting a noisy `info` rule is a natural thing to do, and it silently switched off a `must` gate. Found by the batch-3 review | Stands (batch-3 review) |
| D34 | A finding about hidden content (a hidden comment, a run of hidden characters) is matched across a diff by a fingerprint of all of it, not by its message | The message quotes 60 characters and replaces numbers, so an edit past the quote or a growing run matched the base's finding and passed. Found by the batch-3 review | Stands (batch-3 review) |
| D35 | `ctxlock eval` gets its own runner, built from spike S1's harness, not a promptfoo provider | The harness does all the work that matters (isolation, observe-and-deny, transcripts). promptfoo would add about 850 packages, a native database, network features to switch off, and a Node floor above ctxlock's, and would still leave arms, base caching, variance and the units-loaded join to ctxlock | Stands (S1) |
| D36 | An adherence probe must name a tool the model does not already choose, checked against a no-context arm before it is committed | In S3, naming ruff changed nothing because the model already uses ruff, which would read as "this context does nothing". The other four tools flipped from 0 of 3 to 3 of 3 | Stands (S3) |
| D37 | Plan 2's load collector cannot rely on `InstructionsLoaded` alone | When Claude Code reads `AGENTS.md` through its fallback (no `CLAUDE.md` in the project), no hook fires and nothing in the output mentions it, though the agent follows the file (S3, 30 runs). Every other load matched ctxlock's prediction (S4) | Stands (S3, S4); the collector marks those loads *predicted* (Plan 2, Task 4) |
| D38 | A probe's copy of the repository has its execution config removed: `.claude/settings.json` and `.claude/settings.local.json` at any depth, `.mcp.json`, and `hooks` in the frontmatter of markdown under `.claude/` | `--setting-sources project` loads the project's settings, hooks included, and a skill's own hooks run while it is active. Observe-and-deny stops the agent's tool calls, not hooks, so a pull request could otherwise run a command on the CI runner just by being evaluated | Stands (Plan 2, Task 1); the final review widened it to any letter case and to `allowed-tools`, and a file whose path would land outside the copy is dropped |
| D39 | The run's hook also denies `Read`, `Glob` and `Grep` outside the copy, and no output carries what the agent tried or replied | `Read` can open any path the runner can, including the process environment that holds the Claude credential. In a public repository, a comment or log quoting the agent's commands would carry out whatever it had read | Stands (Plan 2, Tasks 2 and 6) |
| D40 | When base and head both define a probe, the base's definition runs | The same reasoning as D30: a pull request should not rewrite the test that judges it. The report says when the head edits a probe | Stands (Plan 2, Task 5) |
| D41 | Eval results are cached by the git tree, the probe, the model and Claude Code's version, not by the context units alone | What the agent does depends on files that are no unit: `package.json` naming the package manager changes the command a probe checks | Stands (Plan 2, Task 5) |
| D42 | Behavioral results are advisory. The opt-in gate fails a probe only when every base run passed, no head run did, both arms had at least 3 valid runs, and the base defined it | At 3 runs against 3, all-to-none is a one-sided Fisher p of 0.05, the strongest result 3 runs can give. Anything weaker would fail pull requests on noise | Stands (Plan 2, Task 5) |
| D43 | Plan 2 leaves out `ctxlock build` (Plan 3), golden tasks, a Codex collector, L12, the `none` arm, and fork pull requests | `build` is a separate subsystem. Golden tasks execute commands. Codex has no one with access. Fork pull requests get no secrets, and `pull_request_target` would hand a fork's context an agent holding the repository's credential | Stands (Plan 2) |
| D44 | Run folders keep instructions from above them out with `claudeMdExcludes`, and ctxlock refuses to run below an `AGENTS.md` or a `.claude/skills` it cannot exclude | S1 found `~/.claude/CLAUDE.md` loading into every run. Claude Code 2.1.292 matches `claudeMdExcludes` against absolute paths for User, Project and Local files, but `AGENTS.md` comes through a plugin and skills are not memory files | Stands, checked live: an ancestor `CLAUDE.md` with a canary did not load, and a control run without the setting loaded it ([report](../docs/dogfood/2026-11-06-behavioral.md)) |
| D45 | Prompts go to Claude Code on stdin, not as an argument | A drafting prompt carries the unit's text, and the first live draft, on a 38 KB `AGENTS.md`, failed with `ENAMETOOLONG`: Windows allows 32,767 characters on a command line. `claude -p` with no prompt argument reads stdin; 40,121 characters arrived intact | Stands (Plan 2, Task 9) |
| D46 | Where `probe draft` keeps nothing, probes are written by hand and reviewed once | On the dogfood repositories it kept 1 of 9 candidates; most were discarded under D36 because the repository already says the same thing elsewhere | Stands; whether D36 is too strict for probes that only guard against regressions is open |
| D47 | The run hook fails closed, and each run is checked against it: a tool call that acts but never reached the hook stops the check | Claude Code goes ahead with a tool call when its hook exits with anything but 2, so a hook that crashed let the call run. The stream lists every call Claude Code made; any `Bash`, `PowerShell` or edit there with no matching hook event means isolation failed, whatever the cause. Found by the final review | Stands (Plan 2, final review) |
| D48 | Claude Code runs with the runner's full environment, not a minimal one | A minimal environment would break Bedrock, Vertex, proxy and custom-CA setups in ways only live runs on each show. The environment matters only if something runs, and the hook, the strip (D38) and switching off skills' inline shell stop that | Stands; if a fourth way to run something turns up, it would also reach the Claude credential |
| D49 | `ctxlock build` writes the Claude Code and Codex targets itself; rulesync stays the backend for agents ctxlock does not model yet | For these two agents a target is a byte copy of a skill, a one-line `@AGENTS.md`, or an `AGENTS.md` assembled from files Claude Code loads. S2 found rulesync appends path rules to the root `AGENTS.md` and inlines the root files into each other, and ctxlock can check its own output with its own resolvers | Stands (Plan 3); Cursor and Copilot get rulesync with their prediction |
| D50 | "Never overwrite" means never write over a file ctxlock did not generate, or one edited since | A generated file whose source changed, and which still has the recorded digest, is ctxlock's to rewrite. Each file is checked again as it is written | Stands (Plan 3) |
| D51 | Drift of generated files is the lint rule `L14-generated`, not a `ctxlock check` command | `lint`, `diff` and the Action then report it with nothing new to run | Stands (Plan 3) |
| D52 | A generated file an agent would cut is not written | Each fill is scanned on an overlay of the repository first; a file cut by its agent helps no one, and splitting content to fit is a person's job in Phase 1 | Stands (Plan 3) |
| D53 | The docs index is printed, never written, in the format of Next.js's `agents-md` codemod (MIT) | Vercel's result came from an index of a framework's own docs for tasks about that framework. Whether an index of a repository's docs helps is measured with a probe, so ctxlock suggests and the team decides | Stands (Plan 3) |
| D54 | `.ctxlock/generated.json` records digests with CRLF read as LF, as unit digests are | With raw digests, a record written on a Windows CRLF checkout would read as edited on Linux CI. Found by a CRLF test file, before anything shipped | Stands (Plan 3) |
| D55 | `build` never fills into a gitignored path | Generated files are meant to be committed. Found live: plano gitignores `.agents`, and the first fill wrote five skill copies there that ctxlock's own reader then reported missing | Stands; git decides, through `git check-ignore`, so `.git/info/exclude` and global excludes count too (Plan 3, final review) |
| D56 | `build` removes a file from a skill copy once the skill no longer has it, if nobody edited it | A copy mirrors its source. Left behind, the file stays in Claude Code's view of the skill, and `L14` reports it with no command that clears it. Only ctxlock's own unedited output is removed, checked again as it is removed, so D50 holds | Stands (Plan 3, final review) |
| D57 | `build` drops a fill that would make an agent cut a file it loads in full today | A generated root `AGENTS.md` can push a folder's hand-written `AGENTS.md` past Codex's 32,768 bytes. The fill would cost a person's file its place, which is worse than the gap it closes | Stands (Plan 3, final review) |
