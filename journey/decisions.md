# Decisions

Every significant decision, why it was made, and whether it still stands. Reversals are kept rather than edited away, because the reversal is usually the more useful record.

## Direction

| # | Decision | Reasoning | Status |
|---|---|---|---|

| D7 | Name: ctxlock, replacing ContextFS | ContextFS collided with contextfs.ai, a paid AI-memory product. ctxlock was free on GitHub, npm, PyPI and crates.io, and unregistered on four domains | Stands. Trademarks not yet checked (open item before 1.0) |

| D29 | A gitignored file the agent still uses on this machine is read locally: `CLAUDE.local.md` and `.claude/settings.local.json` | Claude Code loads the first and runs the hooks in the second. CI never sees either, since it reads git refs | Stands (Task 7 extended D17's rule to settings) |
| D30 | `ctxlock diff` judges a pull request with the base branch's `harnesses`, `limits` and `lint` settings, not the pull request's own | The check exists partly to catch hostile changes; a pull request that could set `L1-hidden-unicode: off` in the same change would pass itself. | D31 | The dogfood pass fixed `should` and `info` false positives too, not only `must` ones, wherever a reader would dismiss the finding on sight and a rule could tell the same thing from the repository | The plan asked only for `must` fixes, and there were no `must` findings. | D32 | `L9-stale` counts a path as present when it is gitignored, or when it exists under another folder | Gitignored paths are outputs, and monorepo instructions name paths relative to a package. | D33 | Only `L2-exec-config-changed` controls the gate on execution-affecting changes. `diff` compares the full inventory, whatever `L2-exec-config`'s severity or `lint.ignore` say | Quieting a noisy `info` rule is a natural thing to do, and it silently switched off a `must` gate.
