# Static dogfood: four public repositories

**Date:** 2026-11-06 · **ctxlock:** `main` at 09c4e5c, plus the rule fixes this report led to · **Plan:** Task 14 of [the static-core plan](../superpowers/plans/2026-11-05-ctxlock-static-core-and-spikes.md)

ctxlock's static checks were run on four public repositories, and every finding got a verdict. The goal was to find false positives before anyone else does, and to check that the two Phase 1 exit items, (c) and (d), behave as the design says.

**Result:**
- **No `must` findings** on any of the four, so no `must` false positives.
- **131 findings** before the fixes, 98 after. All 33 removed were false positives or duplicates; the fixes are below.
- **Seven false positives remain**, all `should`, and one finding is unsure. They are listed under [What is left](#what-is-left).
- **Both planted-edit checks pass in both directions.**

## The repositories

The plan asked for three repositories that between them have an `AGENTS.md`, a `CLAUDE.md` and a skill directory, confirmed with `gh api repos/<r>/contents/<path>`. The three candidates it named lack a `CLAUDE.md`, so `openai/openai-agents-python` replaced `openai/codex`, which has none of the three at its root. `getsentry/sentry` was added as a fourth because it uses a pattern seen in `vercel/next.js` and `PostHog/posthog` too: `.claude/skills` is a symlink to `../.agents/skills`.

| Repository | Commit | What it has |
|---|---|---|
| `vercel-labs/skills` | `cabe072` | `AGENTS.md` (11,876 bytes); `skills/` is a library of skills to install, not a folder any agent loads |
| `anthropics/skills` | `ca45fc4` | `skills/` with 19 skills, also a library |
| `openai/openai-agents-python` | `814de8b` | `AGENTS.md` (38,241 bytes); `CLAUDE.md`, a symlink to `AGENTS.md`; 14 skills in `.agents/skills`; `.vscode/settings.json` |
| `getsentry/sentry` | `60070e8` | 6 `AGENTS.md` and 4 `CLAUDE.md` (each only `@AGENTS.md`); 29 skills in `.agents/skills`, with `.claude/skills` a symlink to it; `.claude/settings.json`, `.mcp.json`, `.vscode/settings.json`; CODEOWNERS |

The first three were cloned with `git clone --depth 1` and checked with `node dist/cli.js scan <dir> --format json` and `node dist/cli.js lint <dir>`. Sentry's working tree is large, so it was cloned with `--depth 1 --filter=blob:none --no-checkout` and read at `HEAD` through ctxlock's git reader, the same reader `ctxlock diff` uses for the base. That fetches only the files ctxlock reads.

Two things were right before any fix:
- **Symlinks.** In openai-agents-python, `CLAUDE.md` became an alias of the `AGENTS.md` unit, so Claude Code is predicted to load the 38,241-byte file. In sentry, the `.claude/skills` symlink made each of the 29 skills visible to both agents. The one exception is correct: `scraps-review` sets `disable-model-invocation`, so Claude Code leaves it out of its listing.
- **Zero units in `anthropics/skills`.** No agent loads anything from that repository when you work in it, because `skills/` is not a folder any agent reads. That is the right answer for the question ctxlock asks, but it means a skill library gets no checks. See [What is left](#what-is-left).

## What changed

Each fix has a regression test that failed first. All 19 mutations of the new code were killed.

| Rule | Change |
|---|---|
| `L9-stale` | Gitignored paths are skipped, reading the `.gitignore` in each folder above the path |
| `L9-stale` | A path that exists under another folder (`tools/lint/src/ast/utils.ts` for `src/ast/utils.ts`) is not stale. A skill's own `scripts/`, `references/` and `assets/` are excluded, so another skill's script cannot stand in for this one's |
| `L9-stale` | Placeholder names (`foo`, `bar`, `baz`, `qux`, `my-…`, `your-…`) and an extension on its own (`.json`) are skipped |
| `L4-discoverable` | `## Project overview` is not an overview heading. An overview heading inside another's section is not reported again |
| `L2-risky-instruction` | `ANTHROPIC_BASE_URL` and `OPENAI_BASE_URL` are flagged only when set with `=` or followed by a URL |
| `L11-coverage` | A file that is nothing but imports is not listed |
| `L3-budget` | A Codex skill catalog shared by several sites is reported once |

## What is left

**False positives that remain, 7 in all, plus one unsure:**
- **Bare file names that live elsewhere:** `skills-lock.json` ×2 (written in users' projects), and `flagpole.yaml` ×3 and `generate.py` (in another repository). Nothing in the text says where a bare name lives. Use `lint.ignore` in `ctxlock.yaml` for now.
- **A branch name that looks like a path:** `docs/pr-draft-summary-guidance`.
- **Look-alike descriptions from one template** (`L7`, unsure): word overlap cannot tell "frontend" from "backend" in an otherwise identical sentence.

**Gaps:**
- **Skill libraries are not checked.** `anthropics/skills` and the `skills/` folder of `vercel-labs/skills` hold skills that are installed elsewhere, so no agent loads them here, and the spec checks (`L0-skill-spec`, `L6`, `L7`) never run on them. A flag or a `ctxlock.yaml` setting to treat a folder as skills would cover this.
- **A second tree in a file that already has one is not a new finding in `diff`.** The tree finding's message is the same apart from its numbers, and `diff` ignores numbers when matching findings. The budget growth still shows.
- **`L11` could say why** a skill with `disable-model-invocation` reaches Codex only, since that is the opposite of what its author asked for.
- **Speed was not measured.** Sentry took 2 min 24 s, but nearly all of it was the blobless clone fetching files one at a time over the network.
