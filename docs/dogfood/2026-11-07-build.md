# Build dogfood: `ctxlock build` on real repositories

**Date:** 2026-11-07 · **ctxlock:** `main` during [Plan 3](../superpowers/plans/2026-11-07-ctxlock-build.md) Task 8, plus the fix this pass led to · **Plan:** Task 8

`ctxlock build` and `--fill-missing` were run on four repositories:
- the three public repositories from the behavioral dogfood ([report](2026-11-06-behavioral.md)), at the same commits;
- the fixture from spike [S2](../spikes/S2-rulesync.md), built to have the three problems the spike asked about.

`build` runs no agent, so this pass cost nothing and took seconds per repository.

**Result:**
- **Every gap ctxlock could close, it closed, and lint agreed.** The filled units dropped out of `L11` and `L13`. A second `--fill-missing` wrote nothing.
- **Both directions of drift worked on a real repository.** Editing a source made `L14` report the generated file stale, and the next fill rewrote it. Editing the generated file made `L14` report the edit, and the fill left it alone.
- **One real bug, fixed:** on plano, `--fill-missing` wrote five skill copies into a gitignored folder.

| S2 fixture | A skill only Codex reads; a rule for `src/api/**` only Claude Code reads; a `CLAUDE.md` that does not import `AGENTS.md` | A copy of the skill, and `src/api/AGENTS.md` from the rule | The two root files, which need a person's edit; the report quotes `L13`'s fix |

What the budget table showed:
- **openai-agents-python:** Claude Code's skill catalog went from 0 to 1,897 characters, since it can now see the skills.
- **plano:** Codex's always-on bytes at the root went from 0 to 4,789: it had read no instructions at all. Importing `skills/AGENTS.md` takes Claude Code's always-on bytes, for work in `skills/`, from 4,790 to 77,044. That file is already past Codex's limit. Claude Code has no total limit, so the import is written, and the budget table shows the cost before anyone commits it.

On the S2 fixture, the drift report found what the spike found by reading: `CLAUDE.md and AGENTS.md: 2 lines only in CLAUDE.md, 3 only in AGENTS.md`. Unlike rulesync in S2, `build` scoped the API rule to `src/api/AGENTS.md`, so Codex loads it only when it works there, and it copied nothing into the root files.

## The bug: a gitignored folder

plano gitignores `.agents` (`.gitignore` line 154). The first fill wrote five skill copies into `.agents/skills`, where they could never be committed. ctxlock's own working-tree reader lists only files git would track, so the next `lint` reported all five as `missing` (`L14`) while they sat on disk.

**Fix:** a gitignored target is a gap, `.agents/skills/check is gitignored`. It is read from the repository's own `.gitignore` files, in each folder up to the root, the same check `L9` already used, now shared by both. A test pins it for a skill copy, a scoped `AGENTS.md` and a `CLAUDE.md`, and four mutations of the check are each caught.

## Both directions, on plano

| Step | Result |
|---|---|
| Fill | `AGENTS.md` and `skills/CLAUDE.md` written; `.ctxlock/generated.json` records them |
| Add a line to `CLAUDE.md` | `L14`: `AGENTS.md is out of date: CLAUDE.md changed since it was generated` |
| Fill again | `Wrote: AGENTS.md`, with the new line; `L14` gone |
| Add a line to `AGENTS.md` by hand | `L14`: `AGENTS.md was edited after ctxlock generated it` |
| Fill again | `AGENTS.md` left as edited; the report lists it as `edited by hand` |
| Delete the generated files and the record | `git status` clean |

## What this changes

- **The behavioral and static checks now have a writer beside them,** and it only writes what can be committed. The gitignore check is the kind of thing only a real repository shows.
- **The cost of a fill is shown before it is made.** plano's `skills/AGENTS.md` is one import away from 72 KB more always-on context for Claude Code. Whether that is worth it is the team's call, and the table makes it visible.
- **Skills were the most common gap.** In two of the three public repositories, most of what one agent missed was skills the other could not see.
