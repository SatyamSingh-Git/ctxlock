# Dogfood: diagnose, on a planted miss

**Date:** 2026-11-12 · **Where:** a fixture repository at `F:\ctxlock-live\loop\repo`, outside this one · **Plan:** [Plan 8](../superpowers/plans/2026-11-12-ctxlock-diagnose.md)

**Question:** given a miss whose cause is known, does `ctxlock diagnose` name the unit's fault, propose a fix that would have prevented it, and show by replay with real Claude Code that the fix changes what the agent does, without touching the repository?

**Answer:** yes, twice in two runs. Both diagnoses were `defect`, both fixes replaced the rule's one wrong line, and both replays went from 0 of 2 to 2 of 2. The repository was unchanged afterwards. Nothing went to GitHub.

## Why a planted miss

Plan 7 checked signal detection on the author's real sessions. None of the real corrections there is joined to a unit of the repository it came from, and `claude -p` prompts never count as typed, so no real miss was available to diagnose (D88). The fixture plants one whose cause is known.

## The fixture

- **The repository:** `.claude/rules/deps.md` says "Install packages with npm install." Its `package.json` has `"packageManager": "pnpm@9.12.0"`. It also has a one-line `CLAUDE.md` and is committed.
- **The session,** written in Claude Code's own transcript shape:
  - the person asks "add the dayjs package so we can format dates";
  - the agent runs `npm install dayjs` and says it is done;
  - the person writes "no, we use pnpm here".
- **The collector's record:** the session's start, with `CLAUDE.md` and the rule loaded at once.
- **Where they live:** the collector's events in a scratch `CTXLOCK_HOME`, and the transcript in a scratch `CLAUDE_CONFIG_DIR`.
- **One wrapper:** real Claude Code, run with that `CLAUDE_CONFIG_DIR`, would find no login. So `--claude` pointed at a five-line script that removes the variable and runs `claude.exe`. ctxlock itself read the scratch folder, as a person with their own `CLAUDE_CONFIG_DIR` would have it do.

The script that builds all of this (`live8.mjs`) is kept in the session's scratchpad.

`ctxlock misses --min-sessions 1` found the correction and routed both units, since both loaded in the only session.

## What was run

```
ctxlock diagnose rule/.claude/rules/deps.md F:/ctxlock-live/loop/repo --claude <wrapper> --workdir F:/ctxlock-live/loop/work --drafts F:/ctxlock-live/loop/drafts
```

It was run once in text and once with `--format json`, with the defaults: `--runs 2`, and `eval.model`, which is Sonnet (`claude-sonnet-5-5`). `--open` was not used.

## Results

| | First run | Second run |
|---|---|---|
| Verdict | `defect` | `defect` |
| Rests on | "Install packages with npm install." | the same |
| The fix replaces that line with | "Install packages with pnpm add (pnpm install for all dependencies)." | "Install packages with pnpm add (pnpm install for existing dependencies). Do not use npm." |
| The probe | "Add the dayjs package to the project so we can format dates.", expecting a command matching `pnpm (add\|install) dayjs` | the same |
| Base, as the repository is | 0 of 2 | 0 of 2 |
| Head, with the fix | 2 of 2 | 2 of 2 |
| Replay | `validated` | `validated` |
| Claude Code runs | 5 | 5 |
| Time | 35 s | 39 s |

The first run's reason: "The file instructs installing packages with npm install, the agent followed it, and the person wanted pnpm."

**What else was checked:**
- **The repository:** `git status` was clean after both runs.
- **The run folders:** removed, as `eval` removes them.
- **The proposal file:** written on the first run. On the second it was rewritten, since nobody had edited it, and it held the second diagnosis. It has the fix as a diff, the probe as YAML, the replay, and none of the session's own text.
- **The second run's JSON:** both arms ran on `claude-sonnet-5-5`, with 2 turns a run, and the target rule loaded in all 4 of its replay runs.

## What it shows, and what it doesn't

- **The rule beat the repository.** No base run, in either replay, ran a command the probe accepts, though `package.json` names pnpm. Every head run did. That is the miss the fixture planted, and the reason a wrong rule is worth finding. The run folders are gone, so what each base run ran instead isn't recorded.
- **The fix's wording varied between runs, and the probe didn't.** The probe is the part to keep: it is what says the next edit to the rule still does its job.
- **2 runs a side is a direction, not proof.** 0 of 2 to 2 of 2 has a one-sided Fisher p of about 0.17. The Wilson intervals overlap: base 0 to 0.66, head 0.34 to 1. `--runs 3` would give 0.05 at 0 of 3 to 3 of 3, which is the bar `eval` gates on.
- **One planted miss is not a measure of diagnosis on real sessions.** It shows the parts work end to end with real Claude Code. How often a real miss gets the right verdict is for the sessions that produce them.
