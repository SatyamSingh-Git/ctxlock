# Graph dogfood: `who-uses`, `impact` and `L15` on a real repository

**Date:** 2026-11-08 · **ctxlock:** `main` at the end of [Plan 4](../superpowers/plans/2026-11-08-ctxlock-graph.md) Task 6 · **Plan:** Task 7

[openai/openai-agents-python](https://github.com/openai/openai-agents-python), at the commit the behavioral dogfood left it on, after reverting its planted edits ([report](2026-11-06-behavioral.md)). It has 14 skills in `.agents/skills`, an `AGENTS.md`, a `CLAUDE.md` and a CODEOWNERS file, and no `ctxlock.yaml`.

Its skills already name each other: `implementation-kickoff` sends the agent to `code-change-verification` and `implementation-final-review`, and three more skills call `code-change-verification`. A `ctxlock.yaml` declared four of those references as `depends-on`, plus one consumer for the repository itself:

```yaml
version: 1
units:
  .agents/skills/implementation-kickoff:
    depends-on: [.agents/skills/implementation-strategy, .agents/skills/code-change-verification, .agents/skills/implementation-final-review]
  .agents/skills/implementation-final-review:
    depends-on: [.agents/skills/code-change-verification, .agents/skills/pr-draft-summary]
  .agents/skills/test-coverage-improver:
    depends-on: [.agents/skills/code-change-verification]
  .agents/skills/sensitive-logging-audit:
    depends-on: [.agents/skills/code-change-verification]
consumers:
  sdk-development:
    owner: "@sdk-maintainers"
    harnesses: [claude-code, codex]
    depends-on: [AGENTS.md, .agents/skills/implementation-kickoff]
```

Then a line was added to `code-change-verification/SKILL.md`, and the commands ran with the working tree as the head. Nothing was committed, and both files were restored afterwards.

**Result:**
- **`who-uses` and `impact` answered from the declared edges and CODEOWNERS.** The consumer was reached through `implementation-kickoff`. The owners to ask were the CODEOWNERS owners of the changed skill plus the consumer's owner.
- **The pull request comment showed every owner as code.** Three real GitHub handles from CODEOWNERS appeared in it, and none of them would have been notified.
- **`lint` reported nothing for the clean graph, and both findings planted after it:** a reference to a skill that was not there, as a rename leaves behind, and an unmet tier.
- **No bug was found.** `impact` took 12 s, about what `diff` took on the same two refs (11 s). Reading the base ref through git is the slow part; a single scan of the working tree took 2 s.
- **`eval` was not run live.** Its selection by impact is covered by tests against the stand-in for Claude Code. A live run would only re-check what the behavioral dogfood checked, at the cost of subscription runs.

## `L15`, both directions

With the graph above, `lint` gave no `L15` finding. Then `test-coverage-improver` was pointed at `.agents/skills/verify-change`, as a rename leaves behind, and the consumer was made to require `AGENTS.md@certified`:

```
should  L15-graph  ctxlock.yaml  .agents/skills/test-coverage-improver depends on .agents/skills/verify-change, which is no unit
should  L15-graph  ctxlock.yaml  consumer sdk-development needs AGENTS.md at certified; it is reviewed
```

The clean direction is the run before the two edits, on the same file.
