# Dogfood: misses, on real sessions

**Date:** 2026-11-11 · **Where:** the author's own Claude Code sessions in three repositories:
- `F:\ContextFS`, ctxlock itself;
- ElevenPowers;
- a private project.

**Plan:** [Plan 7](../superpowers/plans/2026-11-11-ctxlock-misses.md)

**Question:** does `ctxlock misses` find every interrupt and correction in the sessions the collector recorded, with the right times, and join each to the units that were in context?

**Answer:** yes, after two fixes this run found.
- **The cross-check:** a separate script, written without ctxlock's code, scanned the same transcripts with the same rules. It agreed on every count and every time, in all three repositories.
- **The join:** a hand check of the collector's events confirmed it for the private project's two interrupts.
- **The two fixes:**
  - the plan's rule for which units were "in play" joined no real signal to any unit;
  - the output called two different situations by one misleading name.

## What was run

`ctxlock misses <repo> --format json --excerpts`, and the text output with `--min-sessions 1`, in each repository. It only reads: nothing was written into any of them. One `--drafts` run wrote into a scratch folder.

**The cross-check** (`compare7.mjs`, kept in the session's scratchpad):
- it lists the sessions the collector recorded under each repository;
- it finds their transcripts by session ID;
- it applies the rules from the plan: an exact interrupt line; a typed prompt, after an answer, whose 160-character opening, with pasted text taken out, matches the phrase list.

## Results

| Repository | Sessions | With a transcript | Interrupts | Corrections | Before the collector recorded the session | Joined to a unit |
|---|---|---|---|---|---|---|
| `F:\ContextFS` | 5 | 1 | 1 | 2 | 3 | 0 |
| ElevenPowers | 10 | 1 | 0 | 1 | 1 | 0 |
| The private project | 17 | 6 | 2 | 0 | 0 | 2, to its `CLAUDE.md` |

The script's numbers were the same in every column, and its signal times matched to the millisecond.

**The private project's two interrupts:**
- **The session:** it started at 14:28:24 on 2026-11-09, and its `CLAUDE.md` loaded a second later. The interrupts came at 14:34:43 and 14:46:02.
- **"In its turn" is empty:** the file loaded at the session's start, turns before.
- **The draft** named the repository by its `origin`, said there were no owners in `ctxlock.yaml` or CODEOWNERS, and counted 1 session of 3 that loaded it.

**Why the other two joined nothing:**
- **`F:\ContextFS`:** it has no `CLAUDE.md`, `AGENTS.md`, rules or skills of its own. The only loads the collector saw there are the author's user-level `~/.claude/CLAUDE.md` and plugin skills, and both are outside the repository. Its three signals came on 2026-11-08, before the collector recorded that session's first event.
- **ElevenPowers:** its one correction came on 2026-10-23, weeks before the collector was installed.

**Sessions without a transcript:** 4 of the 5 in `F:\ContextFS` have a single event, a session start, and no prompt. Claude Code writes no transcript for a session nobody typed into.

**Time:**
- **ElevenPowers:** `misses` took 9.5 s. That includes reading its 157 MB transcript.
- **The private project:** `misses` took 101 s, but reading its six transcripts took under a second.
- **Where the rest went:** scanning the repository, which `scan` (117 s) and `loads` (125 s) also spend there. That is an existing cost of scanning that repository, not one this plan added.

## What broke

**The plan's rule joined nothing.**
- **The rule:** a signal's units are those loaded in its turn (D80 as first written).
- **The first run:** of 6 real signals in three repositories, it joined none to a unit.
- **Why:** the collector records `CLAUDE.md`, rules and nested files loading when a session starts, or when the agent first opens a file. People stop or correct the agent many turns later. The file is still in context then, since Claude Code keeps a loaded file for the rest of the session. The plan was checked against transcripts, but not against when loads happen.
- **The fix:** a signal's units are everything loaded before it in the session. The turn is kept as "in its turn", the closer link.

**One name for two situations.** Signals that joined nothing were reported as "before any unit loaded". Two different things hid behind that:
- **A repository with no units of its own in context:** now "With no unit of this repository in context".
- **A session the collector was installed partway through:** what was in context then is unknown, not empty. Now counted apart, and joined to nothing, as "Before the collector recorded the session".

## What was checked and was fine

- **This session's transcript looked like it was in two project folders,** `F--ContextFS` and `f--ContextFS`. Windows paths ignore case, so they are one folder; a cut-short listing made them look like two.
- **Transcripts that quote the markers:** this very session searched for `[Request interrupted by user]` and for Claude Code's rejection text in tool output. Neither was counted. Only an exact text line from the person counts.

## What wasn't checked

- **A unit reaching the default threshold of 3 sessions.** None did here: the one joined unit had 1 session.
- **A rejected tool use.** There is none in the data, since the author runs in auto mode. The signal is left out until there is one to check against (D78).
- **Redaction on real text.** The corrections in these sessions hold no token, email or path, so redaction had nothing to change. Its tests use built-up token shapes.
