# Dogfood: the exit demo, from a miss to a fix in two consumers

**Date:** 2026-11-13 · **Where:** local repositories in `F:\ctxlock-live\outcomes`, outside this one · **Plan:** [Plan 9](../superpowers/plans/2026-11-13-ctxlock-outcomes.md)

**Question:** Phase 3's exit, from §6 of the design: "an end-to-end demo from a real miss to a shipped fix in N consumers, with each step timed." Does each command do its part on one chain?

**Answer:** yes.
- **The chain:** `misses` found the miss and `diagnose` validated a fix. The fix was committed with its probe, and two consumers synced it. `outcomes` found the fix shipped, timed it, and counted 2 consumers reached, and `verify` held 3 of 3.
- **Time:** the commands took 54 seconds in all. The fix shipped 1 minute 52 seconds after the signal.
- **What changed it:** the run found one thing to fix: `outcomes` printed that time as "0.0 days".
- **Nothing left the machine:** nothing went to GitHub, and no repository was changed except by the person's own commit and the consumers' `sync`.

**The miss is planted**, as in Plan 8 (D88): none of the author's real corrections is joined to a unit of its repository. So this shows the parts work end to end. It does not measure the loop on real misses (D95).

## The fixture

The script that builds it, `live9.mjs`, is kept in the session's scratchpad.
- **`org`:** a git repository. Its `.claude/rules/deps.md` says "Install packages with npm install." Its `package.json` names pnpm.
- **`consumers/web` and `consumers/docs`:** git repositories whose `ctxlock.yaml` takes that rule from `org` through `upstream:`.
- **One session in `org`, written in Claude Code's own shape and dated at the time of the run:**
  - the person asks to add dayjs;
  - the agent runs `npm install dayjs`;
  - the person writes "no, we use pnpm here".

  The collector's record of the session is in a scratch `CTXLOCK_HOME`, and its transcript in a scratch `CLAUDE_CONFIG_DIR`.
- **A wrapper for real Claude Code:** it drops that `CLAUDE_CONFIG_DIR`, so Claude Code keeps its own login (Plan 8's report has why).

## What it shows, and what it doesn't

- **The fix and its probe travel as one commit,** and that commit is the only record ctxlock needs. Reach came from the consumers' own locks, at the fixed digest.
- **Both windows are pending,** as they must be on the day a fix ships. The tests cover them closed: held, missed again, no sessions, a later edit, and a window across a month's end in another time zone.
- **The planted session's loads have no digest,** since the fixture wrote `sha256: null`. So its version is "unknown bytes", and no session after the fix is judged. A real collector records the digest.
- **What the run fixed:** `outcomes` printed the time to fix as "0.0 days". A fix that ships within the hour is the goal, and the number hid it. Times under a day now read in hours or minutes (`08a0388`).
- **The person's part was a script** that applied the proposal's diff and probe as written. A person reading the proposal takes longer, and that time belongs in the number.
